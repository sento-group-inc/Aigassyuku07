# AI合宿 第7回 — 会社用ダッシュボード構築キット

1泊2日で、参加企業が**自社の業務ダッシュボードを1本作り、本番URLで開ける状態**にして持ち帰るためのリポジトリ。

講義は [koizumi-dashboard](https://github.com/sento-group-inc/koizumi-dashboard)（小泉会計ダッシュボード）で実際に使われた手順とキット構成を、サニタイズした汎用版として配る。

> このREADMEは合意前のドラフト。構成が確定したら内容を差し替える。

## 参加者が持ち帰るもの

| # | 持ち帰るもの | 何ができるようになるか |
|---|---|---|
| 1 | 自社ダッシュボード（Vercel本番URL） | 自社の1業務が、ログインして一覧・更新できる |
| 2 | `CLAUDE.md` + `docs/` | AIが作業前にスキーマ・UIガイドライン・ロードマップを読んでから着手する |
| 3 | `docs/roadmap.md`（スライス一覧） | 以降は「次のスライス」をAIに渡すだけで機能を足せる |
| 4 | 外部連携の鍵の棚卸し表 | どのツールに何のキーが要るかが分かり、Secret投入まで自分でできる |

## 開発の流れ（伊澤さんへのヒアリングより）

koizumi-dashboard で実際に回った手順。講義もこの順で進める。

1. **ClaudeのArtifactsで画面プロトタイプを作る**（まだコードにしない）
2. **スキーマを組ませる** — ER図をArtifactsで作り、テーブル・カラム・関連の**漏れ**を潰す
3. **実装ロードマップ（スライス一覧）を書かせる** — 手前で価値が出る順に切る
4. **外部ツール連携に必要なキー・アカウントの表を作る**
5. **ツール接続 → Secret投入 → リポジトリ作成 → コードをダウンロード**
6. **`docs/` を整える** — スキーマMD（意思決定の背景ごと残す）／UIガイドライン（同じ指摘を繰り返さない）／インフラ
7. **`CLAUDE.md` に「作業前に読むドキュメント」を書く** — UIガイドラインとデータモデルを読んだ上で着手させる
8. **ロードマップ通りにスライスを切って、PR → レビュー → 修正 → マージを繰り返す**
9. デプロイして、自社URLで開ける状態にする
