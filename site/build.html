作る — 10ステップ

実際にある会社のダッシュボードを作ったときに回った順序です。この順番に意味があります。Step 0（環境の確認）は環境のページで済ませています。

このページを終えると、自社の画面が本番URLで開き、ログインして一覧が見えます。

たとえるなら

家づくりです。前半（1〜5）は打ち合わせと図面、後半（6〜10）は基礎を打って1部屋ずつ建て、鍵を渡すところまで。図面が固まる前に柱を立てると、全部やり直しになります。

順序の考え方

ポイントは「コードを書く前に決め切る」ことと、「手前で価値が出る順に出す」ことです。迷ったら、いつでもガイドに「次は何をすればいい？」と聞けば、今どこかを判定してくれます。

  1. Step 1. 題材を決めて、READMEを書く

    何を作るかを、業務の困りごとから決めます。AIが質問し、答えをファイルに残します。

    Codex: $grill-with-docsClaude: /grill-with-docs文章でも: 「grill-with-docsで〜して」
    あなたがやること
    事前準備で書いた困りごとメモと帳票の項目名を貼り、AIの番号付きの質問に「1はA、2は推奨でOK」のように答える
    終わりの状態
    README.md の冒頭に「〈誰〉が〈何〉に困っている。〈何〉が見えると嬉しい。」があり、CONTEXT.md に業務の言葉が3つ以上ある

    コツ: 大きい課題を選ばないこと。「案件の進捗が全員に見えない」くらいの粒度が最適です。

  2. Step 2. 画面を作る

    コードはまだ書きません。見た目と操作を先に固めます。段ボールで家具の置き場所を試すようなものです。

    Codex: $dashboard-screenClaude: /dashboard-screen文章でも: 「dashboard-screenで〜して」
    あなたがやること
    AIが作った画面をブラウザで開いて触り、「ここは要らない」「これが先に見たい」と言う
    終わりの状態
    docs/prototype.html があり、ブラウザで開いて操作できる。「明日の朝いちばんに何を見るか」に答えられる

  3. Step 3. スキーマとER図を作る

    画面に出ている情報を全部書き出し、どの棚（テーブル）のどの段（項目）に置くかを決めます。

    Codex: $dashboard-schemaClaude: /dashboard-schema文章でも: 「dashboard-schemaで〜して」
    あなたがやること
    AIが出した表とER図を見て、「この情報はどこに入る？」と1つずつ聞く。足りない項目を言う
    終わりの状態
    docs/schema.md にテーブル一覧とER図があり、画面の全項目の置き場所に答えられる

    ここが一番大事です。スキーマが固まると、あとの作業が一気に速くなります。曖昧なまま進むと、実装してから作り直しになります。

  4. Step 4. ロードマップを書く

    スキーマが固まった瞬間に、確認できる単位（スライス）に切ります。コース料理の順番を決めるようなものです。

    Codex: $dashboard-roadmapClaude: /dashboard-roadmap文章でも: 「dashboard-roadmapで〜して」
    あなたがやること
    並び順を見て、「先に見たいもの」が上に来ているか確かめる
    終わりの状態
    docs/roadmap.md に番号付きのスライスがあり、S1は「ログインして一覧が見える」になっている

  5. Step 5. キーとアカウントを棚卸しする

    外とつながる箇所を洗い出し、必要な鍵（キー）と、その置き場所を決めます。鍵そのものは表に貼りません。

    Codex: $dashboard-keysClaude: /dashboard-keys文章でも: 「dashboard-keysで〜して」
    あなたがやること
    表を見て、使うサービスに漏れがないか確かめる
    終わりの状態
    docs/keys.md に表があり、値はどこにも書かれていない。最低限はSupabaseの2つ（Project URL と Publishable key）

  6. Step 6. 土台を作る（DB・アプリ・リポジトリ）

    倉庫（Supabase）を借り、ログイン画面つきの店舗の箱（with-supabaseテンプレート）を建て、鍵を決まった場所にしまいます。

    Codex: $dashboard-repoClaude: /dashboard-repo文章でも: 「dashboard-repoで〜して」
    あなたがやること
    1. database.new でSupabaseのプロジェクトを作る（Project name は my-dashboard、Region は Asia-Pacific、Enable automatic RLS にチェック。パスワードは Generate a password で作ってパスワード管理ツールへ）
    2. ターミナルでアプリの箱を作り、キットの中身をコピーする
      cd ~/Documents
npx create-next-app@latest --example with-supabase my-dashboard
cd my-dashboard
rsync -a --exclude .gitignore --exclude setup.sh --exclude .env.example ../Aigassyuku07/kit/ ./
cp .env.example .env.local
    3. Supabaseの画面上部の Connect を押し、Project URL と Publishable key を .env.local に貼る
    4. npm run dev → localhost:3000 を開く
    5. gh repo create my-dashboard --private --source=. --push でGitHubへ
    終わりの状態
    localhost:3000 で画面が開き、GitHubにリポジトリがある。.env.local はGitHubに上がっていない

    ここから先は、新しくできた my-dashboard フォルダをCodex（またはClaude）で開き直して進めます。キットのスキルとdocsはコピー済みなので、そのまま guide に聞けます。

  7. Step 7. docsとAGENTS.md / CLAUDE.mdを整える

    スキーマの背景、画面の原則、インフラ、ロードマップを埋めます。新人向けの引き継ぎノートを作るようなものです。

    Codex: $dashboard-docsClaude: /dashboard-docs文章でも: 「dashboard-docsで〜して」
    あなたがやること
    AIに「docsを読んで、空欄を埋める質問をして」と頼み、答える
    終わりの状態
    AGENTS.md の「作業前に読む」から全部たどれる。空欄が残っていない（「未確定」は可）

  8. Step 8. ログインと一覧を作る（S1）

    社員証で開くドアを付け、ドアの内側に一覧を置きます。ドアそのものはテンプレートに付いています。

    Codex: $dashboard-authClaude: /dashboard-auth文章でも: 「dashboard-authで〜して」
    あなたがやること
    1. Supabase → Authentication → Sign In / Providers → Allow new users to sign up をオフ（知らない人が登録できないように）
    2. Authentication → Users → Add user → Create new user。Auto Confirm User にチェックして自分のアカウントを作る
    3. AIにテーブルとダミーデータのSQLを書いてもらい、説明を読んでから SQL Editor で Run
    4. AIに一覧画面を作ってもらい、ログアウト状態で開く → ログイン画面に飛ぶことを確かめる
    5. dashboard-slice でPR → マージ
    終わりの状態
    ログインしないと一覧が見えず、ログインするとダミーデータの一覧が見える。PRがマージされている

    RLS（行ごとの鍵）は必ず付けます。付けないと、公開キーを知っている人なら誰でもデータを読めてしまいます。dashboard-auth はRLS付きのSQLを書きます。

  9. Step 9. 本番へ出す

    お店のシャッターを開けます。倉庫の棚（データベース）を先に整え、それから店（アプリ）を開けます。

    Codex: $dashboard-deployClaude: /dashboard-deploy文章でも: 「dashboard-deployで〜して」
    あなたがやること
    1. vercel.com/new → my-dashboard の Import
    2. Environment Variables に .env.local と同じ2つを入れて Deploy
    3. 出たURLを、Supabase → Authentication → URL Configuration の Site URL と Redirect URLs に入れる
    4. 本番URLを開いてログインし、一覧が動くことを確かめる
    終わりの状態
    本番URLを開き、ログインして一覧が動く。URLが docs/infra.md に書かれている

    キーが写る画面は撮らないでください。撮る必要があるときは、値の部分を隠してから撮ります。

  10. Step 10. 次の一手を決めて、振り返る

    明日の自分へのメモを残します。料理のあとにレシピへ書き込むのと同じです。

    Codex: $reflectClaude: /reflect文章でも: 「reflectで〜して」
    あなたがやること
    ガイドに次のスライスを1つ選んでもらい、reflect が出した学びの案から残すものを選ぶ
    終わりの状態
    「明日はこれをやる」が1行で書かれ、学びが1つ以上ファイルに残っている

時間が押したとき

次の順で優先します。残りのスライスが書かれていることが、明日以降の自走に一番効きます。

優先やること理由
1本番URL（Step 9）「できた」の実感が次につながる
2ロードマップ（Step 4）明日自分で進められる
3スキーマ（Step 3）後からでも直せる
4画面の作り込み一番後回しでよい

覚えること（3つ）

  1. コードを書く前に決め切る（Step 1〜5はkitフォルダで言葉と設計）
  2. 最初のスライスはログインして一覧が見えるに固定
  3. 迷ったらガイドに「次は？」。順番を暗記しなくていい
