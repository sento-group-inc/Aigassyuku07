作る — 10ステップ

実際にある会社のダッシュボードを作ったときに回った順序です。この順番に意味があります。Step 0（環境の確認）は環境を整えるで済んでいます。

このページを終えると、自社の画面が本番URLで開き、ログインして一覧が見えます。

たとえるなら

家づくりです。前半（1〜5）は打ち合わせと図面、後半（6〜10）は基礎を打って1部屋ずつ建て、鍵を渡すところまで。図面が固まる前に柱を立てると、全部やり直しになります。

どのStepでも使う一言

迷ったら、いつでもこれを貼れば、今どこかを判定して次の一手を返してくれます。各Stepのプロンプトは、ガイドが案内してくれる内容を先回りして載せたものです。

AIに貼る（Codex / Claude の入力欄へ）
次は何をすればいい？ guide で現在地を判定して、次の一手を1つだけ教えて。コマンドはあなたが実行して。

  1. Step 1. 題材を決めて、READMEを書く

    何を作るかを、業務の困りごとから決めます。AIが質問し、答えをファイルに残します。

    入力欄で /grill-with-docs と打って候補から選ぶCodexは $grill-with-docs でも可文章でも: 「grill-with-docsで〜して」
    あなたがやること
    事前準備で書いた困りごとメモと帳票の項目名を貼り、AIの番号付きの質問に「1はA、2は推奨でOK」のように答える
    終わりの状態
    README.md の冒頭に「〈誰〉が〈何〉に困っている。〈何〉が見えると嬉しい。」があり、CONTEXT.md に業務の言葉が3つ以上ある
    AIに貼る（Codex / Claude の入力欄へ）
    grill-with-docs で、私の困りごとを詰めてください。
困りごとのメモ: （ここに貼る）
帳票の項目名: （ここに貼る）
決まったことは README.md と CONTEXT.md に書いてください。

    コツ: 大きい課題を選ばないこと。「案件の進捗が全員に見えない」くらいの粒度が最適です。

  2. Step 2. 画面を作る

    コードはまだ書きません。見た目と操作を先に固めます。段ボールで家具の置き場所を試すようなものです。

    入力欄で /dashboard-screen と打って候補から選ぶCodexは $dashboard-screen でも可文章でも: 「dashboard-screenで〜して」
    あなたがやること
    AIが作った画面をブラウザで開いて触り、「ここは要らない」「これが先に見たい」と言う
    終わりの状態
    docs/prototype.html があり、ブラウザで開いて操作できる。「明日の朝いちばんに何を見るか」に答えられる
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-screen で、README.md の困りごとから画面の試作を docs/prototype.html に作って。ダミーデータで、一覧・詳細・入力の3画面以内。できたらブラウザで開いて。

  3. Step 3. スキーマとER図を作る

    画面に出ている情報を全部書き出し、どの棚（テーブル）のどの段（項目）に置くかを決めます。

    入力欄で /dashboard-schema と打って候補から選ぶCodexは $dashboard-schema でも可文章でも: 「dashboard-schemaで〜して」
    あなたがやること
    AIが出した表とER図を見て、「この情報はどこに入る？」と1つずつ聞く。足りない項目を言う
    終わりの状態
    docs/schema.md にテーブル一覧とER図があり、画面の全項目の置き場所に答えられる
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-schema で、docs/prototype.html に出ている情報をテーブルに落として、ER図つきで docs/schema.md に書いて。

    ここが一番大事です。スキーマが固まると、あとの作業が一気に速くなります。曖昧なまま進むと、実装してから作り直しになります。

  4. Step 4. ロードマップを書く

    スキーマが固まった瞬間に、確認できる単位（スライス）に切ります。コース料理の順番を決めるようなものです。

    入力欄で /dashboard-roadmap と打って候補から選ぶCodexは $dashboard-roadmap でも可文章でも: 「dashboard-roadmapで〜して」
    あなたがやること
    並び順を見て、「先に見たいもの」が上に来ているか確かめる
    終わりの状態
    docs/roadmap.md に番号付きのスライスがあり、S1は「ログインして一覧が見える」になっている
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-roadmap で、docs/schema.md をもとに docs/roadmap.md にスライスを書いて。S1は「ログインして一覧が見える」にして。

  5. Step 5. キーとアカウントを棚卸しする

    外とつながる箇所を洗い出し、必要な鍵（キー）と、その置き場所を決めます。鍵そのものは表に貼りません。

    入力欄で /dashboard-keys と打って候補から選ぶCodexは $dashboard-keys でも可文章でも: 「dashboard-keysで〜して」
    あなたがやること
    表を見て、使うサービスに漏れがないか確かめる
    終わりの状態
    docs/keys.md に表があり、値はどこにも書かれていない。最低限はSupabaseの2つ（Project URL と Publishable key）
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-keys で、docs/roadmap.md に必要な外部サービスとキーの置き場所を docs/keys.md に表にして。値は書かないで。

  6. Step 6. 土台を作る（DB・アプリ・リポジトリ）

    倉庫（Supabase）を借り、ログイン画面つきの店舗の箱（with-supabaseテンプレート）を建て、鍵を決まった場所にしまいます。

    入力欄で /dashboard-repo と打って候補から選ぶCodexは $dashboard-repo でも可文章でも: 「dashboard-repoで〜して」
    あなたがやること
    1. ブラウザで: database.new でSupabaseのプロジェクトを作る（Project name は my-dashboard、Region は Asia-Pacific、Enable automatic RLS にチェック。パスワードは Generate a password で作ってパスワード管理ツールへ）
    2. AIに頼む: 下のプロンプトを貼る。アプリの箱を作り、キットの中身をコピーし、.env.local を開いてくれる
    3. ブラウザで: Supabaseの画面上部の Connect を押し、Project URL と Publishable key を、開いた .env.local に貼って保存する（値はチャットに貼らない）
    4. AIに頼む: 「続けて」と送る。画面が開くか確かめ、GitHubにリポジトリを作ってくれる
    終わりの状態
    localhost:3000 で画面が開き、GitHubにリポジトリがある。.env.local はGitHubに上がっていない
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-repo の手順2〜6を進めてください。Supabaseのプロジェクトは作りました。
コマンドはあなたが実行してください。.env.local を作ったら、そのファイルを開いて止まってください。
キーの値は私がファイルに直接貼ります（チャットには貼りません）。貼ったら「続けて」と言います。

    ここから先は、新しくできた my-dashboard フォルダをCodex（またはClaude）で開き直して進めます。キットのスキルとdocsはコピー済みなので、そのまま guide に聞けます。

  7. Step 7. docsとAGENTS.md / CLAUDE.mdを整える

    スキーマの背景、画面の原則、インフラ、ロードマップを埋めます。新人向けの引き継ぎノートを作るようなものです。

    入力欄で /dashboard-docs と打って候補から選ぶCodexは $dashboard-docs でも可文章でも: 「dashboard-docsで〜して」
    あなたがやること
    AIの質問に答えて、空欄を埋めてもらう
    終わりの状態
    AGENTS.md の「作業前に読む」から全部たどれる。空欄が残っていない（「未確定」は可）
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-docs で、docs と AGENTS.md / CLAUDE.md を読んで、空欄を埋めるための質問を番号付きでまとめて出して。

  8. Step 8. ログインと一覧を作る（S1）

    社員証で開くドアを付け、ドアの内側に一覧を置きます。ドアそのものはテンプレートに付いています。

    入力欄で /dashboard-auth と打って候補から選ぶCodexは $dashboard-auth でも可文章でも: 「dashboard-authで〜して」
    あなたがやること
    1. ブラウザで: Supabase → Authentication → Sign In / Providers → Allow new users to sign up をオフ（知らない人が登録できないように）
    2. ブラウザで: Authentication → Users → Add user → Create new user。Auto Confirm User にチェックして自分のアカウントを作る
    3. AIに頼む: 下のプロンプトを貼る。テーブルとダミーデータのSQLと、一覧画面を作ってくれる
    4. ブラウザで: AIの説明を読んでから、SQLをSupabaseの SQL Editor に貼って Run
    5. AIに頼む: 「確かめて、PRを作ってマージして」と送る
    終わりの状態
    ログインしないと一覧が見えず、ログインするとダミーデータの一覧が見える。PRがマージされている
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-auth で最初のスライス（ログインして一覧が見える）を作ってください。
Supabaseでのサインアップ停止とユーザー作成は済ませました。
SQLは supabase/migrations/0001_init.sql に書き、何が作られるかを説明してから私に渡してください。

    RLS（行ごとの鍵）は必ず付けます。付けないと、公開キーを知っている人なら誰でもデータを読めてしまいます。dashboard-auth はRLS付きのSQLを書きます。

  9. Step 9. 本番へ出す

    お店のシャッターを開けます。倉庫の棚（データベース）を先に整え、それから店（アプリ）を開けます。

    入力欄で /dashboard-deploy と打って候補から選ぶCodexは $dashboard-deploy でも可文章でも: 「dashboard-deployで〜して」
    あなたがやること
    1. ブラウザで: vercel.com/new → my-dashboard の Import
    2. ブラウザで: Environment Variables に .env.local と同じ2つを入れて Deploy
    3. ブラウザで: 出たURLを、Supabase → Authentication → URL Configuration の Site URL と Redirect URLs に入れる
    4. AIに頼む: 下のプロンプトで確認と記録をしてもらう
    終わりの状態
    本番URLを開き、ログインして一覧が動く。URLが docs/infra.md に書かれている
    AIに貼る（Codex / Claude の入力欄へ）
    dashboard-deploy の手順で、本番URL（ここに貼る）でログインして一覧が動くか確かめる方法を教えて。動いたら docs/infra.md にURLを書いて。

    キーが写る画面は撮らないでください。撮る必要があるときは、値の部分を隠してから撮ります。

  10. Step 10. 次の一手を決めて、振り返る

    明日の自分へのメモを残します。料理のあとにレシピへ書き込むのと同じです。

    入力欄で /reflect と打って候補から選ぶCodexは $reflect でも可文章でも: 「reflectで〜して」
    あなたがやること
    ガイドに次のスライスを1つ選んでもらい、reflect が出した学びの案から残すものを選ぶ
    終わりの状態
    「明日はこれをやる」が1行で書かれ、学びが1つ以上ファイルに残っている
    AIに貼る（Codex / Claude の入力欄へ）
    今日の結果をまとめてください。
- できたこと（本番URLと、動いている操作）
- できなかったこと、詰まった場所
- 次にやるスライス（docs/roadmap.md に印を付ける）
そのあと reflect で、今日の学びを残す案を出してください。

時間が押したとき

次の順で優先します。残りのスライスが書かれていることが、明日以降の自走に一番効きます。

優先やること理由
1本番URL（Step 9）「できた」の実感が次につながる
2ロードマップ（Step 4）明日自分で進められる
3スキーマ（Step 3）後からでも直せる
4画面の作り込み一番後回しでよい

覚えること（3つ）

  1. コードを書く前に決め切る（Step 1〜5はkitフォルダで言葉と設計）
  2. 最初のスライスはログインして一覧が見えるに固定
  3. 迷ったらガイドに「次は？」。順番を暗記しなくていい
