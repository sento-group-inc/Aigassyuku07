README駆動開発

結論: 先に文章を書き、その文章に合わせて作る。コードより先に、言葉を固めます。

このページを読むと、AIに何を渡せば意図通りに動くかが分かります。

なぜ文章から始めるのか

AIは、言われていないことを勝手に決めます。決めた結果が気に入らないと、あとで全部やり直しになります。

逆に、先に決めて文章にしておけば、AIは毎回そこへ戻って作業します。人の記憶も曖昧になりません。

書く順番

  1. 何のためかを1文で書く

    「誰が、何に困っていて、どうなったら嬉しいか」。この1文が全部の判断基準になります。

  2. 画面を言葉にする（または画面を先に作る）

    何が見えるか、何が押せるかを書きます。図や画像の方が早いこともあります。

  3. データの形を書く

    何を、どんな項目で持つか。関連（1対多など）も書きます。ここが一番効きます。

  4. 作業を一覧にする

    確認できる単位に切って、順番を決めます。これがroadmapです。

  5. 決めたことの「なぜ」を残す

    あとで自分が読み返したときに、同じ議論をやり直さずに済みます。

キットでの置き場

ファイル何を書くか
docs/schema.mdデータの形と、そう決めた理由
docs/ui-guidelines.mdUIの原則。指摘されたことを足していく
docs/infra.mdどこで動かすか、秘密情報の置き場
docs/roadmap.md作業の一覧と、終わりの状態
docs/keys.md必要なキーと、その置き場所（値は書かない）
AGENTS.md / CLAUDE.md「作業前に読む」の一覧と、守る決まり

効き方の違い

文章が無いとき文章があるとき
毎回の説明必要不要
AIの判断セッションごとに変わる同じ前提で揃う
作り直し起きやすい起きにくい
引き継ぎできないそのまま渡せる

コツ: 完璧に書こうとしないこと。決まっていない箇所は「未確定」と書いておけば十分です。空欄より「未確定」の方が価値があります。
