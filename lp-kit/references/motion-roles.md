# セクションの役割ごとの動き

動きは飾りではなく、**読む順番・変化・根拠・反応**のどれかを伝える時だけ使う。1つのLPで主役の動きは1〜2個まで。残りは小さな反応（ホバー・フォーカス・押した時）に留める。

この表は、ページ送りの「動くスライド」で使っている6つの動きを、スクロールで読むLP向けに置き換えたもの。

| セクションの役割 | 動き | LPでの作り方 |
|---|---|---|
| ファーストビュー | 段階表示＋署名の瞬間 | 見出し → 補足 → CTA の順に出す。署名の瞬間（商品の価値を体験させる演出）はここか、次のセクションに1つだけ置く |
| 実績・数字 | カウントアップ | 画面に入った時に0から数え上げる。数字は出典のある事実だけ |
| 課題 → 解決 | 前後比較 | ばらばらの要素がスクロールで整列する、Before の画面が After に変わる、など。スクロール量に動きを結びつける |
| 進め方・手順 | ステップ送り | スクロールに合わせて1項目ずつ強調する。左に固定した見出し＋右で流れる手順、など |
| 事例・根拠 | 詳細を開く | 押すと根拠（画面・数字・出典）が開く。最初から全部を見せない |
| 最後の一歩 | 段階表示＋CTAの反応 | CTA のホバー・フォーカス・押した時の反応を作り込む。点滅させ続けない |

## 守ること

- **動きを止めても全部読める**: `prefers-reduced-motion: reduce` の時は、動きで隠していた要素を最初から最終状態で見せる
- **スクロールを乗っ取らない**: スクロール量を勝手に変える・止める演出は、スマホで迷子を生むので使わない
- **速さ**: 小さな反応は 150〜250ms、画面に入る時の動きは 400〜700ms を目安にする。全部を同じ速さにしない
- **軽さ**: 動かすのは `transform` と `opacity` を基本にし、重い演出は画面に入ってから読み込む
- **生成動画を使う大きな演出**（商品が分解する・形が変わる、など）は `oil-motion` を使う。有料の動画生成APIが必要なので、使う前にユーザーに確認する

## 判断に迷った時

[You Don't Need Animations](https://emilkowal.ski/ui/you-dont-need-animations) — 毎回触る場所ほど動きを減らす、という判断基準。
