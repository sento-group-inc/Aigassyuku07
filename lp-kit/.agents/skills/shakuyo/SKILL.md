# shakuyo — 既存ブランドが投下したコストを借用する

人類は既存ブランドの広告投資によって「高級」「誠実」等の視覚・言語コードを学習済みである。その共有辞書を参照するのはタダ。架空ブランドでも書体・署名・写真だけでヘリテージ知覚を d=1.19 生成できる（Pecot et al. 2018）。この構造を成果物づくりの標準工程にする。

根拠: Pecot et al. 2018（書体・署名・写真によるヘリテージ知覚）、Berger & Ward 2010（静かな高級コードと文化資本）。

## ワークフロー

### 1. 印象と受け手を固定する
- ターゲット印象を**1〜2語**で書く（高級／誠実／先端／職人／親密…）。3語以上は絞る。
- **誰の学習済み辞書か**を書く（例: 日本のB2B経営者50代／若年消費者）。コードは受け手の文化資本に依存する（Berger & Ward 2010）。静かな高級コードは、それを読める受け手にしか通じない。

### 2. 参照ブランド群を選ぶ
- その印象で第一想起されるブランドを**5〜10個**列挙。**異業種を混ぜる**（時計×出版×ホテル等）。
- 目的は模倣先ではなく「共通項の母集団」。1業種に寄ると語彙模倣に堕ちる。

#### 2b. LP・Webサイトの場合: 参照URLをAIが自発的に選んで提案する（ユーザーに選ばせない）
ユーザーが参考URLを添えていなくても、参照選定を省略しない。以下のギャラリーをAI側で調査し、**具体的なLP 2〜3本をURL付きで提案**してから抽出へ進む:

| ギャラリー | 用途 |
|---|---|
| [Landbook](https://land-book.com/) / [Godly](https://godly.website/) | 実在LP全般。第一候補 |
| [SaaS Landing Page](https://saaslandingpage.com/) | B2B・SaaS系 |
| [Mobbin](https://mobbin.com/) | アプリUI寄り（LPには補助的に） |

- 提案フォーマット: 各候補に「URL＋なぜこの印象に合うか1行」。ユーザーの返答は採用/差し替えの一言でよい。
- Collect UI（Dribbbleコンセプト集）は部品参考に留め、LP全体の参照には使わない。
- 返答待ちで作業を止めない: 提案を提示したうえで、第一候補ベースで抽出を先行してよい（可逆なため）。

### 3. コード文法を抽出する（Web調査・実物確認）
以下の観点で各ブランドを観察し、**3ブランド以上に共通する要素だけ**を文法として採用する:

| 観点 | 見るもの |
|---|---|
| 書体 | セリフ/サンセリフ、ウェイト、字間 |
| 余白 | 要素密度、マージン比率 |
| 色 | 彩度、色数、コントラスト |
| 写真 | モノクロ/低彩度/自然光、人物の視線、被写界深度 |
| コピー統語 | 文長、言い切り/余韻、数字の出し方、二人称の使い方 |
| 動き・間 | アニメーション速度、ページ遷移、沈黙の量 |

### 4. 類似度チェック
- 抽出した文法が**特定1ブランドを想起させないか**を自問する。「どこかで見た」は借用の失敗（安っぽさ＋法務リスク）。
- 配色そのもの・ロゴ造形・固有のグラフィック要素は**語彙**であり借用禁止。

### 5. 適用表を出して実装する
- 「文法 → この成果物での実装」の対応表を作ってから着手する。
- 実装は成果物の種類に応じて `design-taste-frontend`（LP）へ接続し、`lp` の工程に戻る。

### 6. 事実主張ゼロ確認
- 偽の創業年・偽実績・偽の受賞・架空の顧客数を**1つも含めていない**ことを確認する。コードで語るのは可、事実を偽るのは不可（不真正の露見は基準線以下への転落: Kokkoris & Kamleitner 2026）。

## 完了チェックリスト

- [ ] 印象が1〜2語、受け手の辞書が1行で明記されている
- [ ] 参照ブランドが3個以上・複数業種
- [ ] 採用した要素はすべて3ブランド以上に共通する「文法」である（語彙でない）
- [ ] 特定ブランド想起チェックを通過した
- [ ] 事実主張ゼロ確認を通過した（偽の年号・実績なし）
- [ ] 文法→実装の適用表が成果物に添付されている

## 失敗パターン

| パターン | 症状 | 対処 |
|---|---|---|
| 語彙模倣 | 特定ブランドの配色・ロゴ造形をコピー | 3ブランド共通ルールに戻る。1社にしかない要素は捨てる |
| 事実捏造 | 「Since 20XX」偽装・実績の水増し | 事実主張ゼロ原則。歴史はコードで匂わせ、数字は本物だけ |
| 辞書ミスマッチ | 受け手が読めないコードを使う（インサイダー向け静かな高級を大衆向けに） | Step 1 の受け手固定に戻る |
| 全部載せ | 高級も先端も親密も盛る→流暢性が死ぬ | 印象は1〜2語。矛盾するコードは捨てる |
| 演出過剰 | ヘリテージ風を約束しすぎて後の刷新を縛る（Curse of the Original） | 将来ピボットする面にはヘリテージコードを使わない |

## ルール

- 事実主張ゼロ原則は交渉不可。演出（コード）と虚偽（事実の捏造）の線を越えない。
- 借用は文法レベルまで。語彙（固有の配色・造形・スローガン）は借りない。
- 印象・受け手・参照群・適用表を成果物と同じ場所に残す（再現性）。
