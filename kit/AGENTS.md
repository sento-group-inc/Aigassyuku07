# プロジェクト指示（Codex用の入口）

合宿で作る自社ダッシュボードのリポジトリ。**まずこのファイルを読み、次に下の「作業前に読む」を読んでから着手する。**

## このプロジェクトの目的

自社の業務を1つ選び、その進捗・状況が全員に見えるダッシュボードを、**自分たちで作って公開できる**状態にする。完成度より、本番URLで1画面が動くことを優先する。

## 作り方の流れと前提（毎回守る）

1. **粗く作る**（安いモデル）→ 2. **研究する**（賢いモデル）→ 3. **計画する**（賢いモデル）→ 4. **ゼロから作り直す**（安いモデル）。詳細は `docs/guide-steps.md`。

- **要望・気づき・決定・詰まりは、出たその場で `docs/log.md` に書く。** 作業前に必ず読む。会話とAIの記憶は、モデルやセッションを替えると消えるため。
- **モデルを替える前に、ここまでをログとファイルに書く。** 次のモデルに渡るのはファイルだけ。
- **作り直しでは `mvp/` のコードを流用しない。** 計画（`docs/`）だけを見て作る。`mvp/index.html` は見た目の参考に見るだけ。
- 段階ごとの使うモデルは `ai-setup` に従う。

## 作業前に読む

着手の前に、必ず該当するものを開いて読む。

| ファイル | いつ読むか |
|---|---|
| `docs/guide-steps.md` | 毎回。いまのステップと次の一手がここにある |
| `docs/log.md` | 毎回。要望・決定・詰まりの記録 |
| `docs/research.md` | 計画・実装の前。研究で分かったこと |
| `docs/roadmap.md` | 実装に入る前。どのスライスをやるか |
| `docs/schema.md` | データを触る前。テーブルとカラムの意味 |
| `docs/ui-guidelines.md` | 画面を作る前。同じ指摘を二度しないための原則 |
| `docs/infra.md` | 環境・公開・秘密情報を触る前 |
| `docs/keys.md` | 外部連携を足す前。必要なキーと置き場所 |

## スキル

スキルの実体は`.claude/skills/<名前>/SKILL.md`（Codexは`.agents/skills/`から同じものを読む）。ユーザーが「〈名前〉で」と言ったら、そのファイルを読んでから従う。

| 名前 | 何をするとき |
|---|---|
| `guide` | 「次は何をすればいい？」と聞かれたとき。現在地を判定して次の一手を1つ出す |
| `ai-setup` | 段階ごとに使うモデルを確認・切り替えるとき。PC全体へ恒久反映したいとき |
| `dev-log` | 要望・気づき・決定・詰まりが出たとき。モデルやセッションを替える前 |
| `dashboard-mvp` | 段階1。安いモデルで粗いMVP（`mvp/index.html`）を作るとき |
| `dashboard-research` | 段階2。賢いモデルでMVPとログを研究し `docs/research.md` に残すとき |
| `grill-with-docs` | ユーザーしか知らないことを、番号付きの質問で詰めてファイルに残すとき |
| `dashboard-plan` | 段階3。作り直すための計画一式を作るとき |
| `dashboard-schema` | スキーマとER図を作り、漏れを潰すとき |
| `dashboard-roadmap` | 実装をスライスに切ってロードマップを書くとき |
| `dashboard-keys` | 外部連携に必要なキーを棚卸しするとき |
| `dashboard-docs` | `docs/`と`AGENTS.md`/`CLAUDE.md`を整えるとき |
| `dashboard-repo` | 段階4。Supabase・アプリの土台・GitHubリポジトリを作るとき |
| `dashboard-auth` | ログインして一覧が見える状態（最初のスライス）を作るとき |
| `dashboard-slice` | 1スライスを実装→PR→レビュー→マージするとき |
| `dashboard-deploy` | 本番へ出すとき |
| `poteto-mode` | 「開発をガイドして」と言われたとき。足りないものから次の一手を出す |
| `pstack-guide` | 開発の原則（足す前に引く、実物で示す等）を確認するとき |
| `reflect` | 一区切りついたとき。学びをdocsやスキルへ残す案を出す |
| `eli5` | 前提知識のない人にやさしく説明するとき |
| `lp-guide` | 参考サイトや部品から画面の見た目を作るとき |

## 守る決まり

- **実データを入れない。** 顧客名・個人情報・本番の接続情報はこの段階では扱わない。ダミーデータで作る。
- **キーの値はファイルに書かない。** `docs/keys.md`には「どこにあるか」だけ書く。値は環境変数かSecretへ。
- **スライス単位で止める。** 1つのPRで1つの確認可能な変化。大きくなったら分ける。
- **完了と言う前に実物を見る。** ビルドが通ったではなく、画面が本番URLで開くこと。
- **UIは`docs/ui-guidelines.md`に従う。** `mvp/index.html`は見た目の参考に見るだけで、コードは流用しない。

## 進め方

1. `guide`スキルで現在地を確認し、次の1手を受け取る
2. その1手を実行する（分からなければ同じスキルへ戻る）
3. 終わりの状態を満たしたら`docs/guide-steps.md`のチェックを付ける
4. 繰り返す
