# プロジェクト指示（Codex用の入口）

合宿で作る自社ダッシュボードのリポジトリ。**まずこのファイルを読み、次に下の「作業前に読む」を読んでから着手する。**

## このプロジェクトの目的

自社の業務を1つ選び、その進捗・状況が全員に見えるダッシュボードを、**自分たちで作って公開できる**状態にする。完成度より、本番URLで1画面が動くことを優先する。

## 作業前に読む

着手の前に、必ず該当するものを開いて読む。

| ファイル | いつ読むか |
|---|---|
| `docs/guide-steps.md` | 毎回。いまのステップと次の一手がここにある |
| `docs/roadmap.md` | 実装に入る前。どのスライスをやるか |
| `docs/schema.md` | データを触る前。テーブルとカラムの意味 |
| `docs/ui-guidelines.md` | 画面を作る前。同じ指摘を二度しないための原則 |
| `docs/infra.md` | 環境・公開・秘密情報を触る前 |
| `docs/keys.md` | 外部連携を足す前。必要なキーと置き場所 |

## スキル

スキルの実体は`.claude/skills/<名前>/SKILL.md`。ユーザーが「〈名前〉で」と言ったら、そのファイルを読んでから従う。

| 名前 | 何をするとき |
|---|---|
| `guide` | 「次は何をすればいい？」と聞かれたとき。現在地を判定して次の一手を1つ出す |
| `dashboard-screen` | 画面プロトタイプをArtifactsで作るとき |
| `dashboard-schema` | スキーマとER図を作り、漏れを潰すとき |
| `dashboard-roadmap` | 実装をスライスに切ってロードマップを書くとき |
| `dashboard-keys` | 外部連携に必要なキーを棚卸しするとき |
| `dashboard-docs` | `docs/`と`AGENTS.md`/`CLAUDE.md`を整えるとき |
| `dashboard-slice` | 1スライスを実装→PR→レビュー→マージするとき |
| `dashboard-deploy` | 本番へ出すとき |
| `pstack-guide` | 開発の進め方（原則・検証）を確認するとき |
| `jev-guide` | 曖昧な判断を型つきで出したいとき |
| `lp-guide` | 参考サイトや部品から画面を作りたいとき |

## 守る決まり

- **実データを入れない。** 顧客名・個人情報・本番の接続情報はこの段階では扱わない。ダミーデータで作る。
- **キーの値はファイルに書かない。** `docs/keys.md`には「どこにあるか」だけ書く。値は環境変数かSecretへ。
- **スライス単位で止める。** 1つのPRで1つの確認可能な変化。大きくなったら分ける。
- **完了と言う前に実物を見る。** ビルドが通ったではなく、画面が本番URLで開くこと。
- **UIは`docs/prototype.html`を手本にする。** ゼロから考え直さない。

## 進め方

1. `guide`スキルで現在地を確認し、次の1手を受け取る
2. その1手を実行する（分からなければ同じスキルへ戻る）
3. 終わりの状態を満たしたら`docs/guide-steps.md`のチェックを付ける
4. 繰り返す
