# 実行環境

> これは雛形。Step 5〜7で、実際に選んだ構成に合わせて書く。

## 構成

| 層 | 何を使うか | なぜ |
|---|---|---|
| データベース | （例）Supabase (PostgreSQL) | 無料枠で始められ、SQLがそのまま使える |
| アプリ | （例）Next.js | 画面とサーバーを1つのリポジトリで扱える |
| ホスティング | （例）Vercel | GitHubにつなぐだけで公開できる |

## 公開の流れ

1. GitHubへpush
2. ホスティングが自動でビルド
3. 発行されたURLで確認

## 秘密情報の置き場

| 何 | どこに置くか | 誰が見られるか |
|---|---|---|
| DBの接続情報 | ホスティングの環境変数 | 管理者のみ |
| APIキー | 同上 | 同上 |
| ローカルの開発用 | `.env.local`（**gitに入れない**） | 自分のみ |

**値をこのドキュメントに書かない。** 置き場所だけ書く。

## 困ったとき

| 症状 | 見るところ |
|---|---|
| 公開したのに古い | 最新のpushがビルドされたか |
| 画面が真っ白 | ビルドのログ、環境変数の不足 |
| DBにつながらない | 接続情報の値、IP制限 |
