# UI/UX 実装ガイドライン

> これは雛形。Step 7で自分たちの指摘を追記していく。**同じ指摘を二度しないための原則集**。個別の画面ではなく、一般ルールとして書く。

`docs/prototype.html`を本番UIのリファレンスとして踏襲する。逸脱するときは理由をここに書く。

## 0. 大原則

- **説明・補足のテキストを画面に置かない。** 「これはこういう仕組み」という注記は製品ではノイズ。設計意図はこのドキュメントに書く。
- **OSの標準UIをそのまま使わない。** ブラウザ標準の`alert()` / `confirm()` / `<select>`は見た目が揃わない。自前の部品にする。
- **スマホで使えることは要件。** 後付けにせず最初から想定する。

## 1. 情報構造

- **一覧と詳細は分ける。** 1件しかないもの（状態・期限）は上部、繰り返すもの（工程・明細）は行の中に置く。
- **業務が増えてもナビの項目を増やさない。** 業務は同一画面内の切り替えで扱う。

## 2. モバイル

- 詳細やフォームはスマホでは下から出す（ボトムシート）。全画面は覆わない。
- 一覧⇔詳細は縦に積まず、切り替えにする。

## 3. 状態と色

- 状態（未着手・進行中・確認待ち・遅延・完了）は、色だけでなく**文字でも**示す。
- 破壊的操作（削除）は色を分け、実行前に確認を挟む。
