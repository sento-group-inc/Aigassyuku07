# dashboard-docs — AIの前提を整える

たとえるなら、**新人向けの引き継ぎノート**。毎朝来る新人（AI）に、同じ説明を口で繰り返さなくて済む。

## なぜやるか

AIは毎回まっさらな状態で始まる。**前提をファイルに書いておけば、毎回説明しなくて済む。**ここを整えるほど、あとの作業が速く・正確になる。

## 手順

1. `docs/schema.md`を埋める。**決定の背景も書く**
2. `docs/ui-guidelines.md`を埋める。実際に指摘されたことを原則として書く
3. `docs/infra.md`を埋める。構成・公開の流れ・秘密情報の置き場
4. `docs/roadmap.md`を最新にする
5. `AGENTS.md`と`CLAUDE.md`の「作業前に読む」から、全部たどれることを確認する

## 書くときの原則

- **背景を残す。** 「なぜこの形か」が無いと、後でAIが同じ議論をやり直す
- 空欄を残さない。決まっていない箇所は「未確定」と明記する
- 実データ・実キーを書かない

## 終わりの状態

- 空欄が残っていない（「未確定」の明記は可）
- AGENTS.md / CLAUDE.mdから全ドキュメントへ辿れる
- 新しいセッションで「このプロジェクトは何か」を聞き直されない

## つまずき

| 症状 | 対処 |
|---|---|
| 何を書けばいいか分からない | AIに「このリポジトリのdocsを読んで、空欄を埋める質問をして」と頼む |
| 更新が面倒になる | 大きい変更のあとだけ更新する。毎回ではない |
