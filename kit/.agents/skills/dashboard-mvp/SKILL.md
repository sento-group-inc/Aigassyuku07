# dashboard-mvp — とにかく粗く作る（段階1）

たとえるなら、**家具を買う前に段ボールで置いてみる**。本物を作る前に、実際に触って「ここが違う」を見つける。段ボールは後で捨てるので、雑でいい。

**使うモデル: 安くて速いモデル**（Codex: Luna / Sol、Claude: Sonnet）。詳しくは `ai-setup`。

## 手順

1. `docs/log.md` を読む。困りごとの1文が無ければ、ユーザーに聞いて先に書く

   > 〈誰〉が〈何〉に困っている。〈何〉が見えるようになると嬉しい。

2. `mvp/index.html` に、1つのHTMLファイルでMVPを作る
   - ダミーデータを10〜20件入れる（実データは使わない）
   - 一覧・絞り込み・1件の編集くらいまで、実際に押して動くようにする（保存はブラウザ内でよい）
   - 見た目は整えすぎない。15〜30分で出す
3. ブラウザで開いてユーザーに渡す（Macなら `open mvp/index.html`）
4. ユーザーが触って言ったことを、その場で `docs/log.md` に `[要望]` `[気づき]` として書く（`dev-log`）
5. 直してほしいと言われたら、小さく直してまた触ってもらう。**2〜3回回したら次の段階へ**

## 守ること

- 作り込まない。ログインもデータベースもまだ要らない（段階4で作る）
- コードはきれいでなくていい。段階4で**ゼロから作り直す**ので、このコードは流用しない
- 触って出た声は、必ずログに残す。ここで出た声が研究の材料になる

## 終わりの状態

- `mvp/index.html` を開いて、ユーザーが自分で操作できる
- `docs/log.md` に、困りごとの1文と、触って出た要望・気づきが5つ以上ある

## つまずき

| 症状 | 対処 |
|---|---|
| 何を作るか決まらない | いま使っているスプレッドシートの列名をそのまま一覧にする |
| 直したい所が止まらない | ログに書いて先へ進む。直すのは作り直しのとき |
| 画面が崩れる | 気にしない。MVPで大事なのは「触って声が出るか」 |
