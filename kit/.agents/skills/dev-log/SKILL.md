# dev-log — 開発ログを残す

たとえるなら、**現場の作業日誌**。職人が交代しても、日誌を読めば昨日の続きから始められる。AIの記憶と会話は、モデルを替えたりセッションが切れたりすると消える。消えて困ることは日誌に書く。

## いつ書くか

- ユーザーが要望・気づきを言ったとき（「ここ使いにくい」「担当ごとに見たい」）
- 何かを決めたとき（「見積は万円単位にする」）
- 詰まったとき、エラーが出たとき
- **モデルやセッションを切り替える前**（ここまでの要点を書く）
- 1つの作業が終わったとき（`済` を付ける）

言われなくても、上に当てはまったら書く。書いたら「ログに書きました」と一言伝える。

## 書き方

`docs/log.md` の「ログ」の末尾に1行ずつ足す。

```text
- 2026-10-06 [要望] 担当者ごとの件数を一覧の上に出したい（営業部長から）
- 2026-10-06 [決定] 見積金額は万円単位で持つ（円単位が要る業務がないため）
- 2026-10-06 [詰まり] 並び順が保存されない → MVPなので研究で扱う
- 2026-10-06 [済] S1 ログインと一覧（PR #1）
```

- 種類は `要望 / 気づき / 決定 / 詰まり / 済` のどれか
- 理由や出どころを括弧で書く。理由のない決定は、あとで同じ議論をやり直すことになる
- 顧客名、個人情報、キーの値は書かない

## 読むとき

- 作業を始める前に必ず読む
- 研究（段階2）と計画（段階3）では、ログ全体が材料になる
- ゼロから作り直す（段階4）ときも、ログの「要望」と「決定」が満たされているかを最後に確かめる

## 終わりの状態

- 今日出た要望と決定が、全部 `docs/log.md` にある
- 別のAIがこのファイルだけ読んでも、何を作っていて何が決まったか分かる
