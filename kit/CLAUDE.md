# プロジェクト指示（Claude用の入口）

合宿で作る自社ダッシュボードのリポジトリ。**作業前に下の「作業前に読むドキュメント」を読み、読んだ上で着手する。**

## このプロジェクトの目的

自社の業務を1つ選び、その進捗・状況が全員に見えるダッシュボードを、自分たちで作って公開する。完成度より、**本番URLで1画面が動く**ことを優先する。

## 作業前に読むドキュメント

該当するものを開いてから着手する。

- `docs/guide-steps.md` — 当日の進行台本。いまのステップと次の一手
- `docs/roadmap.md` — 実装スライス（番号＝実施順）
- `docs/schema.md` — データモデル。**なぜその形にしたかの背景ごと残す**
- `docs/ui-guidelines.md` — UI/UX実装の注意点。壁打ちで出た指摘の原則集で、再発防止のため必読
- `docs/infra.md` — 実行環境・公開・秘密情報
- `docs/keys.md` — 外部連携に必要なキーと置き場所

## 実装の原則

- **UIは`docs/prototype.html`を手本に踏襲**する。ゼロからUIを考え直さない。
- `docs/roadmap.md`のスライス順（番号＝実施順）で、最小単位に分けて進める。1スライス＝1 PR。
- **実データを扱わない。** 顧客名・個人情報・本番の接続情報は使わず、ダミーデータで作る。
- **キーの値をファイルに書かない。** `docs/keys.md`には置き場所だけ。値は環境変数かSecretへ。
- DBアクセスはサーバー側のみ。クライアントへ秘密鍵を出さない。

## スキル

`.claude/skills/`に置いてある。使いたいときは名前で呼ぶ（例: `/guide`）。

| 名前 | 何をするとき |
|---|---|
| `guide` | 「次は何をすればいい？」と聞かれたとき。現在地を判定して次の一手を1つ出す |
| `grill-with-docs` | 題材を決める・計画を詰めるとき。質問で詰めて README / CONTEXT.md / ADR に残す |
| `dashboard-screen` | 画面の試作（`docs/prototype.html`）を作るとき |
| `dashboard-schema` | スキーマとER図を作り、漏れを潰すとき |
| `dashboard-roadmap` | 実装をスライスに切ってロードマップを書くとき |
| `dashboard-keys` | 外部連携に必要なキーを棚卸しするとき |
| `dashboard-repo` | Supabase・アプリの土台・GitHubリポジトリを作るとき |
| `dashboard-docs` | `docs/`と`AGENTS.md`/`CLAUDE.md`を整えるとき |
| `dashboard-auth` | ログインして一覧が見える状態（最初のスライス）を作るとき |
| `dashboard-slice` | 1スライスを実装→PR→レビュー→マージするとき |
| `dashboard-deploy` | 本番へ出すとき |
| `poteto-mode` | 「開発をガイドして」と言われたとき。足りないものから次の一手を出す |
| `pstack-guide` | 開発の原則（足す前に引く、実物で示す等）を確認するとき |
| `reflect` | 一区切りついたとき。学びをdocsやスキルへ残す案を出す |
| `eli5` | 前提知識のない人にやさしく説明するとき |
| `lp-guide` | 参考サイトや部品から画面の見た目を作るとき |

## コミュニケーション

- ユーザーは非エンジニア。専門用語は日常の言葉に置き換える。
- 一度に1つだけ指示する。複数を同時に求めない。
- 手で操作する箇所は「どこを押すか」まで書く。
