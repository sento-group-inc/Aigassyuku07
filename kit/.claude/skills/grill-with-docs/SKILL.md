# grill-with-docs — 質問で詰めて、答えを文書に残す

たとえるなら、**家を建てる前の打ち合わせ**。「部屋はいくつ？」「誰が住む？」を先に決めて、図面に書き残す。口頭で終わらせると、次の打ち合わせで同じ質問が繰り返される。

`grill-me`（質問するだけ）との違いは、**答えをファイルに残す**こと。残した答えは、次にAIが作業するときの前提になる。

## 進め方

### 1. 幹をそろえる（最初に1回）

ユーザーの依頼から次の3つをAIが提案し、OKをもらってから質問に入る。

- **決めたいこと**: 1文で
- **今回は決めないこと**
- **終わりの条件**: 何が決まったら終わりか

### 2. 自分で調べられることは先に調べる

`README.md`、`docs/`、既存のファイルを先に読む。**ファイルを見れば分かることは質問しない。**

### 3. 決めどころを番号付きで一度に出す

1問ずつ聞かない。決めることを全部、番号付きで一度に並べる。各項目に次を書く。

- 背景（なぜ決める必要があるか）
- 選択肢と、それぞれを選んだときにどうなるか
- **推奨**（AIのおすすめと理由）

ユーザーは「1はA、2は推奨でOK」のように番号で答えられる。影響が大きいものほど上に置く。

### 4. 答えをファイルに書く

| 決まったこと | 書く場所 |
|---|---|
| 誰が、何に困っていて、何ができるようになるか | `README.md` の冒頭 |
| この業務で使う言葉の意味（例: 「案件」とは何か） | `CONTEXT.md`（書き方は [CONTEXT-FORMAT.md](CONTEXT-FORMAT.md)） |
| 戻しにくい決定と、その理由 | `docs/adr/0001-〇〇.md`（書き方は [ADR-FORMAT.md](ADR-FORMAT.md)） |

答えが出るたびに、その場で書く。最後にまとめて書かない。

### 5. 終わりの条件を満たしたら締める

決まったこと・書いたファイル・まだ決めていないことを短く報告し、`guide` に戻る。

## 合宿の題材を決めるときの決めどころ（例）

1. 誰の困りごとか（現場の担当者／管理者／経営者）
2. 何が見えると嬉しいか（一覧／期限切れ／担当ごとの件数）
3. 今どこにデータがあるか（スプレッドシート／紙／頭の中）
4. 誰がデータを直すか（全員／担当者だけ）
5. 今日作らないもの（通知、自動集計、他システム連携）

## 終わりの状態

- `README.md` の冒頭に「誰が・何に困っていて・何ができるようになるか」が書いてある
- `CONTEXT.md` に、業務で使う言葉が3つ以上定義されている
- 決めていないことが「未確定」として書いてある

## つまずき

| 症状 | 対処 |
|---|---|
| 質問が多すぎる | 影響の大きい上位5つだけ答え、残りは推奨で進める |
| 答えられない質問がある | 「未確定」と書いて先へ進む。空欄より「未確定」の方が価値がある |
| 話がそれていく | 「幹に戻って」と言う。AIは最初に決めた3つに戻る |
