# ai-setup — AIの初期設定（モデルの使い分け）

たとえるなら、**職人と設計士の使い分け**。手を動かす量が多い仕事は腕の速い職人（安いモデル）に任せ、全体を見直す仕事は設計士（上位モデル）に任せる。全部を設計士に頼むと高くて遅い。全部を職人に任せると、直すべき所に気づけない。

## 原理（モデル名が変わっても使える）

| 仕事 | 使うモデル | なぜ |
|---|---|---|
| 作る・作り直す・定型作業（段階1・4） | **安くて速いモデル** | 量が多い。何度でもやり直せる |
| 研究・計画（段階2・3） | **いちばん賢いモデル** | ここの質が、作り直した後の質を決める |
| 手伝い役のAI（サブエージェント） | **本体より一段下** | 大半の手伝いは最上位の頭を要しない |
| 見直し役のAI（レビュー） | **本体と同じ** | 作った側より弱いと、見落としを拾えない |

モデルの名前は数か月で変わる。名前ではなく「安い／賢い」の役割で覚える。

## 2026年10月時点の例

| 役割 | Codex | Claude |
|---|---|---|
| 安くて速い（作る） | GPT-5.6 Luna / GPT-5.6 Sol | Sonnet |
| いちばん賢い（研究・計画） | GPT-6 Astra | Opus（使えるプランならFable） |

## このキットに入っている設定

- **Claude Code**: `kit/.claude/settings.json` で、手伝い役のAIの既定を `sonnet`（本体Opusの一段下）にしてある。このフォルダの中だけで効く。
- **Codex**: フォルダ単位のモデル設定は効かないので、段階ごとに入力欄右下のモデル選択で切り替える。
- どちらも**PC全体の設定（`~/.codex`、`~/.claude`）は書き換えていない**。

## 段階ごとの切り替え

| 段階 | Codex（入力欄右下） | Claude Code（`/model` と打つ） |
|---|---|---|
| 1 粗く作る | Luna または Sol | Sonnet |
| 2 研究する | Astra | Opus |
| 3 計画する | Astra | Opus |
| 4 ゼロから作り直す | Luna または Sol | Sonnet |

**モデルを替えると、会話の文脈は引き継がれないものと考える。** 引き継ぐのはファイルだけ（`docs/log.md`、`mvp/`、`docs/research.md`、計画のdocs）。替える前に「ここまでをログに書いて」と頼む。

## ユーザーが「PC全体に入れたい」と言ったとき

必ず、何をどのファイルにどう書くかを見せ、**ユーザーの同意を得てから**書く。元のファイルは `〜.bak` として残す。

- Codex: `~/.codex/config.toml` に、安いモデルを既定にし、研究用のプロファイルを足す

  ```toml
  model = "gpt-5.6-sol"

  [profiles.research]
  model = "gpt-6-astra"
  model_reasoning_effort = "high"
  ```

- Claude Code: `~/.claude/settings.json` の `env` に `"CLAUDE_CODE_SUBAGENT_MODEL": "sonnet"` を足す（本体がFableなら `"opus"`）

## 終わりの状態

- 今の段階で使うモデルが言える
- モデルを替える前に、引き継ぐ内容がファイルに書かれている
