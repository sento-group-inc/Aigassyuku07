# dashboard-schema — スキーマとER図

## 手順

1. 画面に出ている情報を**全部**書き出す（1行1項目）
2. 同じものをまとめてテーブルにする
3. ER図を書く（ArtifactsやMermaidで図にする）
4. **漏れのチェック**: 各項目について「これはどこに入るか」を1つずつ確認する
5. **繋がりのチェック**: 1対多・多対多の向きが合っているか確認する
6. `docs/schema.md`へ、**なぜその形にしたか**と一緒に書く

## 漏れを見つける質問

- 「1件」に対して「複数」になるものは何か（→別テーブル）
- 状態はどこに持つか。誰がその状態を変えるか
- いらなくなったとき、消すのか印を付けるのか
- 「昔はこうだった」を残す必要があるか（履歴）

## 終わりの状態

- `docs/schema.md`にテーブル一覧とER図がある
- 画面の全項目が、どのテーブルのどの列に入るか説明できる
- 迷った決定に「なぜ」が書かれている

## つまずき

| 症状 | 対処 |
|---|---|
| 項目が多すぎる | まず1業務だけに絞る。他業務は後で足す |
| 同じ意味の項目が複数ある | 1つに統合し、元の名前を`docs/data-sources.md`に残す |
| 後で変えたくなった | `docs/schema.md`の「決定の記録」に追記してから変える |
