# dashboard-screen — 画面を試作する

たとえるなら、**家具を置く前の段ボール模型**。本物を作る前に、置いた感じを目で確かめる。

## 手順

1. 聞く: 誰が、何に困っていて、何が見えると嬉しいか（1つに絞る）
2. 必要な画面を3枚以内に絞る
   - 一覧（今日見るもの）
   - 詳細（1件の中身）
   - 入力（追加・更新）
3. `docs/prototype.html` として1つのHTMLファイルに作る（Codex・Claude共通）。Claudeのチャット画面を使う人はArtifactsで作ってから保存してもよい
4. 見た目と操作を固める。**動くことより、現場で使える形かを見る**

## 作るときの原則

- 実データを使わない。ダミーの業務名・人名で作る
- 説明テキストを画面に置かない
- 状態（未着手・進行中・確認待ち・遅延・完了）を色と文字の両方で示す
- スマホ幅でも崩れない形にする

## 終わりの状態

- `docs/prototype.html`（または同等の成果物）を開いて、自分で操作できる
- 「この画面で、明日の朝いちばんに何を見るか」に答えられる

## つまずき

| 症状 | 対処 |
|---|---|
| 画面が多くなりすぎる | 3枚に絞る。残りは`docs/roadmap.md`へ回す |
| 見た目が好みでない | 参照したいサイトや既存ツールの画面を1つ挙げてもらい、`lp-guide`へ渡す |
| 何を表示すべきか分からない | いま使っているスプレッドシートの列名をそのまま出してもらう |
