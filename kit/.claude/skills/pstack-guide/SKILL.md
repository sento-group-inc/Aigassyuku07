# pstack-guide — 開発の進め方

「速く行きたいなら、先に深く行く」という進め方。**原則の名前を覚える必要はない。**使う場面だけ知っておけばよい。

## よく使う原則（場面で覚える）

| 場面 | 原則 | やること |
|---|---|---|
| 追加しようとしている | 足す前に引く | 先に不要なものを消す。消せないなら足さない |
| 設計で迷っている | 2〜3案を並べる | 比べてから決める。1案で決めない |
| 作る順番で迷う | 検証できる単位で切る | 1つ確認してから次へ |
| 完了と言いたくなった | 実物で示す | ビルドログでなく、実際に動かした結果を見る |
| エラーが出た | 根本原因を直す | 再現 → なぜ → 根本を直す。握りつぶさない |
| 何度も同じ指示をしている | ルールを構造にする | 文章で足さず、設定・テスト・スクリプトにする |

## poteto-mode（ガイド）

「開発をガイドして」と頼むと、`poteto-mode` スキルが足りないものを1つ見つけ、次の一手を理由付きで案内する。順序を暗記する必要はない。

## reflect（振り返り）

仕事が一区切りしたときに `reflect` スキルを呼ぶ。**今回うまくいった進め方を次に使い回せる形にする**ための振り返り。会話から学びを拾い、どのファイル（スキルや規約）に反映するかの案を出す。

使いどころ:

- 大きい作業が終わったあと
- 遠回りしたあとに、正しい道が見つかったとき
- 「このやり方は今後も使える」と感じたとき

## 終わりの状態

- 次に何を確かめるかが1つに決まっている
- それが「なぜ次なのか」を自分の言葉で言える

## つまずき

| 症状 | 対処 |
|---|---|
| 全部の工程を毎回やりたくなる | 足りない工程だけ選ぶ。小さい修正は軽く進める |
| 調べすぎて進まない | 決めるために必要な差分だけ調べる。調べる目的を1行で書く |
