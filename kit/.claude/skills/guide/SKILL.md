# guide — 進行役

ユーザーは非エンジニア。**一度に1つだけ**指示する。

## 手順

1. `docs/guide-steps.md` を読む
2. リポジトリの実物を見て現在地を判定する（ファイルの有無だけでなく中身を見る）

| 見るもの | 何が分かるか |
|---|---|
| `docs/guide-steps.md` のチェック | 申告された進み具合 |
| `./setup.sh` の結果 | Step 0が終わったか |
| `README.md` の冒頭と `CONTEXT.md` | Step 1が終わったか |
| `docs/prototype.html` が実質あるか | Step 2が終わったか |
| `docs/schema.md` にテーブルとER図があるか | Step 3が終わったか |
| `docs/roadmap.md` にスライスが並んでいるか | Step 4が終わったか |
| `docs/keys.md` の置き場所が埋まっているか | Step 5が終わったか |
| `package.json` と `.env.local` があり、`npm run dev` で開くか | Step 6が終わったか |
| `app/protected/page.tsx` が一覧になっているか | Step 8が終わったか |
| `docs/infra.md` に本番URLがあるか | Step 9が終わったか |

3. 次の一手を**1つだけ**出す

## 出力の形

```text
現在地: Step 3（スキーマとER図）
次の一手: 画面に出ている情報を全部書き出し、テーブルにまとめる
使うスキル: dashboard-schema
あなたがやること: AIが出した表を見て、足りない項目を言う
終わりの状態: docs/schema.md にテーブル一覧とER図があり、「この情報はどこに入るか」に全部答えられる
なぜ今これか: データの形が決まらないと、実装しても作り直しになるため
```

手で操作する箇所があるときは、「どの画面の、どのボタンを押すか」まで書く。

## 守ること

- 一度に複数のステップを指示しない。
- 専門用語を使わない。使うときは括弧で言い換える（例: リポジトリ（コードの置き場））。
- ユーザーが同じ場所で2回詰まったら、**スコープを半分に割って**先に終わらせる。
- 時間が押しているときは、本番 → ロードマップ → スキーマの順で優先する。
- ステップが終わったら `docs/guide-steps.md` のチェックを実際に更新する（口頭で終わりにしない）。

## つまずき別の対処

| 症状 | 対処 |
|---|---|
| 何を作るか決まらない | `grill-with-docs` に切り替え、候補を3つ出して選ばせる |
| 画面の案が出ない | 既存のスプレッドシートや紙を「そのまま画面にする」と伝える |
| エラーが消えない | エラー文をそのまま貼らせる。原因を1つに絞ってから直す |
| 進め方そのものに迷う | `poteto-mode` で現在地と次の一手を出す |
| 時間がない | 今のスライスを半分に割る |
