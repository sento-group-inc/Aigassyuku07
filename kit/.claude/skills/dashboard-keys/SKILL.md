# dashboard-keys — キーの棚卸しとSecret

## 手順

1. ロードマップを見て、外部と繋がる箇所を全部挙げる
2. 何のサービスに、何のために繋ぐかを書く
3. 必要なキーと、その**取得場所**を書く
4. **置き場所**を決める（ローカルの`.env.local`／ホスティングの環境変数）
5. `docs/keys.md`へ表として書く。**値は書かない**
6. リポジトリとプロジェクトを作り、Secretへ登録する

## 置き場所の原則

| 種類 | 置き場所 |
|---|---|
| サーバーだけが使う秘密（DBの管理者キーなど） | ホスティングの環境変数 |
| ブラウザに渡ってよいキー（公開キー） | 環境変数（公開前提のものだけ） |
| ローカル開発用 | `.env.local`（gitに入れない） |

## 終わりの状態

- `docs/keys.md`に表があり、値がどこにも書かれていない
- 必要なキーがSecretに登録されている
- ローカルで`.env.local`を用意してアプリが起動する

## つまずき

| 症状 | 対処 |
|---|---|
| どのキーが要るか分からない | 先にStep 6（最小構成）まで進める。連携は後で足せる |
| キーを間違ってコミットした | その場で無効化して再発行する。履歴から消すより先に無効化 |
| どこに置くか迷う | ブラウザで見えてよいか？を基準にする。駄目ならサーバー側 |
