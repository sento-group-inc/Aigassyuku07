### F6. [Step 7 / dashboard-deploy] Vercel の環境変数で、警告に従うと本番が動かなくなる

- 重さ: 高（進めなくなった。原因の特定に時間がかかった）
- やろうとしたこと: Vercel に `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` を入れて本番に出す
- 起きたこと:
  - Vercel が「`NEXT_PUBLIC_` は値がブラウザに公開される。外して非公開にするか、安全なら種類を Config に」と警告する。名前から `NEXT_PUBLIC_` が外れた状態（`SUPABASE_URL` など）で保存されていた
  - その結果、本番のアプリに値が渡らず、ログインなしで `/protected` を開くと「A server error occurred」になった。ログイン画面は出るので、一見動いているように見える
  - 環境変数を直したあと、再デプロイしないと反映されないことも、手順に無い
  - 最初のデプロイが始まっておらず、`DEPLOYMENT_NOT_FOUND` になる状態もあった（`main` に push するまでデプロイされなかった）
- 期待していたこと: 台本どおりに入れれば動く。警告が出たときの対処が書いてある
- 直し案（あれば）: `dashboard-deploy` に、「Vercel が `NEXT_PUBLIC_` の警告を出す。この2つは公開してよい値なので、名前はそのまま、種類を `Config` にする。`service_role` では絶対にしない」「変数を直したら `Deployments` から再デプロイ」「`/protected` がエラーになったら環境変数の名前を疑う」を足す
- Issue: #24
